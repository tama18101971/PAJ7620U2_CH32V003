# tooling/editor_setup

## Language server (clangd) — required for any symbol-based serena tool

Without an LSP backend, `serena_find_symbol`, `serena_get_symbols_overview`,
`serena_find_referencing_symbols` and diagnostics all fail with
"Active language servers: []"; only `serena_search_for_pattern` / Grep / Read
work. Three parts are needed together:

1. `.serena/project.yml` → `language_servers: [cpp]`. Serena ships its own
   pinned clangd (`~/.serena/language_servers/static/ClangdLanguageServer/clangd/…`,
   19.1.2 at the time of writing) — nothing to install, no PATH change.
   Same setting as the sibling APDS project.
2. `compile_commands.json` at the project root, generated by
   `pio run -t compiledb`; git-ignored. Without it clangd has no WCH SDK
   include paths or `-DCH32V003F4/…` defines. 25 entries; our three sources
   are present with `directory` = project root.
3. `.clangd` in the project root — **mandatory**, two parts:
   - `CompileFlags.Remove` of `-march=rv32ecxw -mabi=ilp32e
     -msmall-data-limit=0 -msave-restore -flto`: native clang dies on
     "unknown target CPU 'rv32ecxw'" and then answers `documentSymbol` with
     `invalid AST (-32001)`, i.e. zero symbols;
   - `CompileFlags.Add` of the toolchain's own include dirs
     (`toolchain-riscv/lib/gcc/riscv-wch-elf/12.2.0/include` and
     `toolchain-riscv/riscv-wch-elf/include`): PlatformIO does not copy the
     compiler's implicit search paths into the DB, so without them clangd
     cannot find `<stdio.h>`/`<stdint.h>` and reports 'file not found' plus a
     cascade of "implicit declaration of printf".
   The real firmware build is unaffected. The same file also serves VS Code
   cpptools and PIO IDE. Paths are machine-specific — fix them locally if
   PlatformIO lives elsewhere.
   `Diagnostics.Suppress` additionally silences `anyx86_interrupt_attribute`:
   `__attribute__((interrupt("WCH-Interrupt-fast")))` describes a QingKe vector
   and only looks wrong to a native x86 clang.

## Lifecycle gotcha

The language server manager is built once per project object and cached for the
whole life of the MCP process. Changing `language_servers` (or fixing
`project.yml`/`.clangd`) has **no effect in the running session** —
`activate_project` on an already-active project short-circuits, and switching
away and back reuses the cached empty manager. A new Serena agent (reload the
IDE window / new session) is required. This is why the offline check below is
the way to prove a fix before restarting anything.

## Offline verification (works in any fresh process)

```powershell
& "$env:USERPROFILE\.serena\language_servers\static\ClangdLanguageServer\clangd\clangd_19.1.2\bin\clangd.exe" --version
$env:PYTHONIOENCODING = "utf-8"
& "$env:USERPROFILE\.local\bin\serena.exe" project health-check "E:\GitProjects\PAJ7620U2_CH32V003"
```

The health check starts the configured servers, calls the symbol tools and
lists them. It ends with a `UnicodeEncodeError` on the "✅" line under a cp1251
console — cosmetic: the check itself already reported success and the log with
per-tool results is written to `.serena/logs/health-checks/`.
Last verified run: clangd up in 0.07 s, 578 symbols indexed for `paj7620.c`.

Useful knobs for the `cpp` server, via `ls_specific_settings` in
`project.yml` (see `ClangdLanguageServer` docstring): `clangd_version`,
`compile_commands_dir`, `ls_base_cmd` (absolute path to a clangd binary if the
managed one is unwanted).

## VS Code

- PlatformIO IDE 3.3.4 + cpptools 1.34.4 installed, platform `ch32v` present.
  If `.vscode/` is missing, the extension never initialised the folder:
  no include paths and no status-bar toolbar. Reload window or
  `File → Open Folder` on the project root (not on `src/`).
- `.vscode/c_cpp_properties.json` and `.vscode/launch.json` are generated
  locally and git-ignored; project paths use `${workspaceFolder}`, SDK paths
  are absolute. `ch32v00x.h` lives in `Peripheral/ch32v00x/inc`, `debug.h` in
  `Debug/ch32v00x`.
- `.vscode/tasks.json` (committed) defines `PIO: Build / Upload / Monitor /
  Clean` calling `pio.exe` by absolute path — build and flash work with the
  extension inactive; `Ctrl+Shift+B` = build.
