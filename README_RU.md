# PAJ7620U2_CH32V003

Драйвер датчика жестов **PAJ7620U2** для микроконтроллера **CH32V003**
(WCH, RISC-V), bare-metal / PlatformIO, без RTOS, без динамической памяти.

API повторяет драйвер [APDS-9960_CH32V003](https://github.com/tama18101971/APDS-9960_CH32V003)
(те же имена функций с префиксом `paj_`, те же коды ошибок, та же распиновка),
поэтому перенос проекта с APDS-9960 сводится к переименованию вызовов —
см. [INTEGRATION_RU.md](INTEGRATION_RU.md).

* Жесты: **вверх, вниз, влево, вправо, вперёд, назад, по часовой стрелке,
  против часовой стрелки, взмах рукой** (распознаёт сам датчик, 120 Гц).
* Маска активных жестов: в сборке (`PAJ_GESTURE_MASK`) и в рантайме
  (`paj_setGestureMask()`); отключённые жесты вырезаются из прочитанных флагов
  и не мешают разрешённым.
* Proximity с автоматической калибровкой порогов.
* Прерывание INT → EXTI (PC3) либо polling.
* Неблокирующий `paj_poll()`: 5 мс расписание, entry-фильтр и cooldown,
  настроенные под управление ладонью (паразитные Z-флаги игнорируются).
* Проверка готовности датчика и самовосстановление после сбоев I2C.
* Флэш: около 2 КБ при LTO, RAM: ~32 байта статики (+ буфер калибровки).

## Подключение

Распиновка полностью совпадает с драйвером APDS-9960 — плата переводится
заменой датчика:

| Сигнал CH32V003 | Вывод PAJ7620U2 | Примечание |
|---|---|---|
| `PC1` | SDA | I2C, open-drain, подтяжка к VDD 3.3 В (4.7 кОм) |
| `PC2` | SCL | I2C, open-drain |
| `PC3` | INT | open-drain, active-low, вход с подтяжкой вверх |
| `PD5` | UART TX | 115200 бод (только для примера/отладки) |
| 3.3 В | VBUS, VDD | 2.8…3.6 В |
| 3.3 В | VLED | **отдельная цепь**: 3.0…4.2 В, пиковый ток ИК-светодиода до 860 мА |
| GND | GND (2 вывода) | землю светодиода и землю логики соединять |

> **Питание светодиода.** Даже в режиме ожидания датчик даёт ток 2.8 мА
> (с учётом пиков LED), а при обнаружении жеста — импульсы до 720…860 мА.
> Модуль питания VLED, разводка и шунтирующая ёмкость у вывода VLED должны
> выдерживать этот ток; типовая замена на «слабый» модуль приводит к
> срывам распознавания при быстрых жестах.

> ⚠️ **Нельзя питать модуль от вывода 3.3 В WCH-Link** (там ≈100 мА). Проверено
> на стенде: при питании VDD/VLED от WCH-Link МК уходит в цикл POR-сбросов,
> как только датчик начинает сканировать (ИК-светодиод просаживает шину), а с
> погашенным датчиком (`pio run -e power_test`) плата работает стабильно
> минутами. Питайте VDD/VLED от отдельного стабилизатора (3.3 В, с запасом по
> току) с bulk-ёмкостью ≥100…470 мкФ и 10 мкФ/100 нФ у выводов модуля; земля
> общая. WCH-Link при этом питает только МК/логику.

## Установка

```ini
lib_deps =
    https://github.com/tama18101971/PAJ7620U2_CH32V003.git#v1.2.0
```

Библиотека тянет за собой `I2C-CH32V003` (пин `#v7.1.0`) — драйвер I2C1
для CH32V003 с bus recovery. Перед первым вызовом `paj_init()` шина должна
быть инициализирована приложением:

```c
i2c_init(400000);        /* 400 кГц — максимум для PAJ7620U2 */
paj_init();
```

## Быстрый старт (polling)

```c
#include "i2c.h"
#include "paj7620.h"

i2c_init(400000);
if (!paj_init()) {
    /* paj_getLastError(): PAJ_ERR_SENSOR_HANG / PAJ_ERR_INVALID_ID / PAJ_ERR_I2C */
}

for (;;) {
    /* now_ms — монотонные миллисекунды приложения (в примере их даёт TIM2). */
    if (paj_poll(now_ms)) {
        gesture_t g = paj_takeGesture();
        switch (g) {
            case GESTURE_UP:    /* ... */ break;
            case GESTURE_DOWN:  /* ... */ break;
            case GESTURE_LEFT:  /* ... */ break;
            case GESTURE_RIGHT: /* ... */ break;
            default:            break;
        }
    }
}
```

Полный пример с UART-выводом, режимом прерываний и демонстрацией proximity —
[examples/basic/main.c](examples/basic/main.c).

## Режим прерываний

```c
#include "paj_int_config.h"

paj_exti_init();          /* PC3 → EXTI3, falling-edge + NVIC */
paj_enableInterrupt();    /* маски 0x41/0x42: INT активен на разрешённые жесты */

for (;;) {
    __WFI();              /* TIM2 (1 мс) и/или INT пробуждают МК */
    if (paj_poll(now_ms)) {
        gesture_t g = paj_takeGesture();
        /* ... */
    }
}
```

`paj_poll()` нужно вызывать регулярно и в режиме EXTI: без нового фронта INT
именно следующие вызовы завершают временное подтверждение бокового жеста
(20 мс). Забирайте жест сразу после `true` от `paj_poll()`: пока готовый
результат не забран, драйвер не читает флаги, а датчик держит INT низким
(active-low вывод снимается только чтением `0x43`/`0x44`).

Все EXTI 0…7 на CH32V003 делят один вектор. Если обработчик уже определён
приложением (как в DriverMD6), соберите библиотеку с
`-DPAJ_PROVIDE_EXTI_ISR=0` и вызывайте `paj_handle_exti()` /
`paj_clear_exti()` из своего `EXTI7_0_IRQHandler`.

## Отключение ненужных жестов

```c
/* При сборке (build_flags), до первого вызова paj_init():
 *   -DPAJ_GESTURE_MASK=PAJ_GESMASK_DIRECTIONS -DPAJ_WAVE_MASK=0
 * В рантайме, в любой момент после paj_init(): */
paj_setGestureMask(PAJ_GESMASK_DIRECTIONS, false);   /* только 4 направления */
```

Готовые наборы в `paj7620_config.h`: `PAJ_GESMASK_DIRECTIONS` (`0x0F`),
`PAJ_GESMASK_SIX_AXIS` (`0x3F`, с Z-осью), `PAJ_GESMASK_ALL` (`0xFF`).
Можно собрать и произвольную комбинацию битов `GES_*`.

Маска работает на двух уровнях: регистры `0x41`/`0x42` перестают дёргать вывод
INT, **и** драйвер вырезает отключённые биты из прочитанных `0x43`/`0x44`.
Без второго шага отключение было фиктивным: датчик выставляет все флаги всегда,
и, например, паразитная пара `Forward|Backward` от широкой ладони отбрасывала
валидный `Left`. Текущую маску возвращают `paj_getGestureMask()` /
`paj_isWaveEnabled()`.

Сам пример `examples/basic` собран именно так: `platformio.ini` задаёт
`-DPAJ_GESTURE_MASK=0x0F -DPAJ_WAVE_MASK=0`, поэтому на стенде доступны только
UP/DOWN/LEFT/RIGHT, а в UART при старте печатается фактическая маска
(`PAJ7620U2 ready. Gesture mask 0x0F, wave off`). Чтобы вернуть все жесты,
замените значения в `build_flags`:
`-DPAJ_GESTURE_MASK=PAJ_GESMASK_ALL -DPAJ_WAVE_MASK=1`.

> Повторный `-D` того же макроса (например, в `platformio.ini` и в
> `PLATFORMIO_BUILD_FLAGS`) — это не «тихое» переопределение: gcc выдаёт
> `warning: "PAJ_GESTURE_MASK" redefined`, а при `-Werror` сборка падает.
> Снимайте проектное значение через `build_unflags` /
> `PLATFORMIO_BUILD_UNFLAGS` (так делает CI-вариант `all-gestures-mask`).

## API

| Функция | Назначение |
|---|---|
| `bool paj_init(void)` | I2C wake-up, конфигурация по datasheet, включение, калибровка |
| `bool paj_sleep(void)` | Пассивный режим: снятие Enable, конфигурация сохраняется |
| `bool paj_wakeup(void)` | I2C wake-up + Enable, сброс состояния жеста |
| `bool paj_shutdown(void)` | Enable = 0 + suspend (IDD_SUS ~15 мкА) |
| `bool paj_poll(uint32_t now_ms)` | Рекомендуемый неблокирующий сервис: расписание, entry-фильтр и cooldown |
| `gesture_t paj_takeGesture(void)` | Забрать готовый жест без ожидания |
| `bool paj_available(void)` | Legacy-опрос без временной фильтрации; жест кэшируется |
| `gesture_t paj_readGesture(void)` | Legacy: забрать жест; без кэша — ждёт до `PAJ_GESTURE_TIMEOUT_MS` |
| `bool paj_readProximity(uint8_t *v)` | PS-данные 0…255 (нужен режим proximity) |
| `bool paj_readStatus(uint8_t *v)` | Состояние автомата датчика: 0 = OP, 1 = S1, 2 = S2 |
| `uint8_t paj_getLastError(void)` | `PAJ_ERR_NONE` / `I2C` / `SENSOR_HANG` / `INVALID_ID` / `UNSUPPORTED` |
| `uint8_t paj_getLastI2CStatus(void)` | Сырой код последней неудачной транзакции i2c.h |
| `uint8_t paj_getReinitCount(void)` | Число последовательных переинициализаций |
| `uint8_t paj_getAmbiguousCount(void)` | Число чтений флагов с неопределённым направлением (только по разрешённым жестам) |
| `bool paj_setGestureMask(uint8_t mask1, bool wave)` | Маска активных жестов в рантайме: фильтр флагов + регистры `0x41`/`0x42` |
| `uint8_t paj_getGestureMask(void)` / `bool paj_isWaveEnabled(void)` | Текущая маска жестов и состояние WAVE |
| `bool paj_recalibrate(void)` | Пересчёт порогов proximity по данным датчика |
| `void paj_enableInterrupt(void)` | Включить прерывания (маски из текущей маски жестов) |
| `void paj_disableInterrupt(void)` | Выключить прерывания |
| `void paj_clearInterrupt(void)` | Снять вывод INT (чтение флагов) |
| `bool paj_setProximityMode(void)` | Переключение в режим proximity (`PAJ_ENABLE_PS_MODE=1`) |
| `bool paj_setGestureMode(void)` | Возврат в режим жестов |

`gesture_t`: `GESTURE_NONE`, `LEFT`, `RIGHT`, `UP`, `DOWN` (значения 0…4 —
как в драйвере APDS-9960), далее `FORWARD`, `BACKWARD`, `CW`, `CCW`, `WAVE`.

## Конфигурация

Все параметры — в [src/paj7620_config.h](src/paj7620_config.h) с
`#ifndef`-дефолтами и проверками диапазонов через `#error`. Переопределяйте
через `build_flags`, а не `#define` в своём `.c` (драйвер компилируется
отдельно).

| Макрос | По умолчанию | Назначение |
|---|---|---|
| `PAJ_GESTURE_MASK` | `PAJ_GESMASK_ALL` (`0xFF`) | Какие из 8 жестов активны (прерывание **и** программный фильтр) |
| `PAJ_WAVE_MASK` | `1` | Жест «взмах» (при `0` и `PAJ_PS_MASK=0` регистр `0x44` не читается) |
| `PAJ_PS_MASK` | `0` | Прерывание по proximity |
| `PAJ_GESTURE_ROTATE` | `0` | Поворот модуля 0/90/180/270° (переназначение направлений) |
| `PAJ_REJECT_AMBIGUOUS` | `1` | `0` — не чистить противоречивые пары флагов |
| `PAJ_XDIR_THRESHOLD` | `0x0D` | Порог влево/вправо (`bank0 0x93`, не входит в init datasheet) |
| `PAJ_YDIR_THRESHOLD` | `0x0A` | Порог вверх/вниз (`bank0 0x94`, не входит в init datasheet) |
| `PAJ_ZDIR_THRESHOLD` | `0x3C` | Порог push/pull (`bank0 0x48`); для ладони поднимать до `0x48…0x55` |
| `PAJ_PROX_THRESHOLD` / `PAJ_PROX_EXIT_TH` | `200` / `64` | Пороги proximity (значения datasheet) |
| `PAJ_ENABLE_CALIBRATION` | `1` | Доступность `paj_recalibrate()` |
| `PAJ_CALIBRATE_ON_INIT` | `0` | Прежнее поведение: калибровать пороги внутри `paj_init()` |
| `PAJ_CAL_SAMPLES` | `16` | Число замеров при калибровке |
| `PAJ_CAL_SIGMA_COEFF` | `3` | Порог = медиана + N·σ |
| `PAJ_CAL_INTERVAL_MS` | `2` | Пауза между замерами |
| `PAJ_POLL_INTERVAL_MS` | `5` | Период чтения флагов в `paj_poll()` |
| `PAJ_GESTURE_CONFIRM_MS` | `20` | Подтверждение бокового жеста; `0` — без задержки |
| `PAJ_GESTURE_COOLDOWN_MS` | `230` | Подавление событий после выдачи; `0` — выключено |
| `PAJ_Z_OVERRIDES_XY` | `0` | `0` — ладонь (Z не отменяет направление), `1` — палец (Z приоритетнее) |
| `PAJ_GESTURE_TIMEOUT_MS` | `300` | Таймаут блокирующего `paj_readGesture()` |
| `PAJ_WAKEUP_TIMEOUT_MS` | `20` | Ожидание готовности датчика (T1 > 700 мкс) |
| `PAJ_OWN_SYSTICK` | `1` | `0` — не трогать SysTick (свой таймер в приложении) |
| `PAJ_RETRY_LIMIT` | `6` | Повторы инициализации/переинициализации |
| `PAJ_REINIT_THRESHOLD` | `3` | Сколько сбоев I2C подряд запускают переинициализацию |
| `PAJ_INT_MODE` | `1` | `0` — polling, `1` — прерывания при старте |
| `PAJ_PROVIDE_EXTI_ISR` | `1` | `0` — обработчик EXTI принадлежит приложению |
| `PAJ_ENABLE_PS_MODE` | `1` | `0` — вырезать режим proximity (~250 Б флэша) |
| `PAJ_EXAMPLE_TRACE` | `0` | Диагностический вывод в `examples/basic` |
| `PAJ7620U2_DEBUG` | — | `-DPAJ7620U2_DEBUG` включает printf драйвера |

## Как это работает

* **Жесты распознаёт датчик.** Хост читает битовые флаги в `0x43`/`0x44`
  (банк 0) и декодирует их; никакой обработки пикселей на MCU.
  Чтение этих регистров **сбрасывает флаги**, поэтому драйвер кэширует
  найденный жест и отдаёт его в `paj_readGesture()`.
  `0x43` читается и декодируется первым и отдельно от `0x44`: сбой чтения
  `0x44` стоит только флага «взмах», но не уже распознанного жеста. Если
  WAVE отключён и `PAJ_PS_MASK=0`, второй регистр не читается вообще — на
  один I2C-обмен меньше на каждый опрос.
* **Отключённые жесты фильтруются дважды.** `0x41`/`0x42` управляют только
  выводом INT, а чип продолжает выставлять все биты в `0x43`/`0x44`. Поэтому
  драйвер накладывает активную маску (`PAJ_GESTURE_MASK` / `PAJ_WAVE_MASK`,
  рантайм — `paj_setGestureMask()`) на прочитанные байты **до** декодирования.
  Без этого шага отключённый жест продолжал выигрывать декодирование и мог
  обнулить разрешённый.
* **Противоречивые пары чистятся, а не всё чтение.** Датчик выставляет биты
  независимо, поэтому при слабом сигнале один жест может дать несколько битов
  сразу (наблюдалось `0x43 = 0x3F`). Каждая антагонистическая пара
  (`Up|Down`, `Left|Right`, `Forward|Backward`, `CW|CCW`) сбрасывается
  поотдельности и считается в `paj_getAmbiguousCount()`, а остальные биты
  остаются пригодными: `Left|Forward|Backward` теперь даёт `Left`, а не
  `GESTURE_NONE`. Рост счётчика означает слабый сигнал: питание
  ИК-излучателя, расстояние до руки, скорость жеста либо неудачные пороги
  `PAJ_XDIR_THRESHOLD` / `PAJ_YDIR_THRESHOLD`.
* **Неблокирующий фильтр.** `paj_poll(now_ms)` читает флаги не чаще 5 мс,
  задерживает боковой жест на 20 мс для подтверждения и на 230 мс блокирует
  повторные события (широкая ладонь проходит над датчиком медленнее пальца).
  При `PAJ_Z_OVERRIDES_XY=0` (по умолчанию) паразитный `Forward/Backward` не
  отменяет начатый боковой жест — именно его даёт край ладони, — а кандидат
  подтверждается сразу, как только датчик перестал выдавать направление.
  `PAJ_Z_OVERRIDES_XY=1` возвращает поведение для пальца: Z выдаётся сразу и
  отменяет ожидающий боковой результат. Готовый жест забирает
  `paj_takeGesture()`; непрочитанный результат не перезаписывается. В режиме
  EXTI `paj_poll()` всё равно нужно вызывать регулярно, чтобы завершить
  временное окно без нового фронта INT; своевременный забор жеста ещё и
  отпускает active-low INT (флаги снимаются тем же чтением).
* **Два банка регистров** переключаются регистром `0xEF`; драйвер отслеживает
  текущий банк и не тратит лишние транзакции на повторный выбор.
* **Пробуждение.** Даташит требует I2C wake-up-команду (START + slave ID +
  STOP) и T1 > 700 мкс, T2 > 400 мкс. До окончания пробуждения датчик не
  отвечает ACK — драйвер это учитывает и не считает ошибкой.
* **Инициализация** — официальная последовательность из datasheet
  («i. Initial», 45 записей: записи маски прерываний и порога Z пишутся
  отдельно), затем пороги gesture engine по осям (`0x93`/`0x94`/`0x48`),
  затем пороги proximity, затем `Enable`, затем маски прерываний. Включение
  подтверждается чтением `bank1 0x72`.
* **Калибровка порогов proximity не выполняется в `paj_init()`**
  (`PAJ_CALIBRATE_ON_INIT=0`). В режиме жестов датчик `0x6C` не обновляет
  («Only functional at proximity detection mode»): значение зависит от
  внешней засветки, и калибровка по нему недетерминирована — на одном модуле
  при одном включении получалось `median=45, sigma=0 -> 45/33`, при следующем
  замеры отбраковывались и оставались `200/64`. Для осмысленной калибровки
  используйте `paj_setProximityMode()` + `paj_recalibrate()`.
* **Отказоустойчивость.** Одиночный сбой I2C в `paj_available()`/внутри
  `paj_readGesture()` только фиксируется в `paj_getLastI2CStatus()`; полная
  переинициализация (wake-up плюс перезапись всей конфигурации) запускается
  после `PAJ_REINIT_THRESHOLD` сбоев подряд, потому что на это время датчик не
  отвечает и все жесты теряются. После исчерпания `PAJ_RETRY_LIMIT` —
  `PAJ_ERR_SENSOR_HANG`.
* **Энергопотребление.** `paj_shutdown()` переводит датчик в suspend
  (IDD_SUS ≈ 15 мкА) — после этого обязателен `paj_wakeup()`, который
  выполняет I2C wake-up. `paj_sleep()` дешевле по последствиям: конфигурация
  сохраняется, пробуждение — одна запись.

## Ограничения и грабли

* **Структурная совместимость.** Драйвер и библиотека I2C используют
  статическое состояние и не реентерабельны: вызов из ISR недопустим.
* **Адресное пространство.** Только 7-битный адрес `0x73`; датчик не
  поддерживает clock stretching и работает на частоте до 400 кГц.
* **Только один жест в датчике и один готовый слот в драйвере.** При
  медленном опросе или долгом непрочитанном результате события теряются.
  EXTI снижает задержку, но не заменяет регулярный `paj_poll()`.
* **Proximity не обновляется в режиме жестов** — `paj_readProximity()`
  вернёт 0, пока не вызван `paj_setProximityMode()`.
* **`SysTick->CNT` не является временной базой**, пока используются
  `Delay_Ms()/Delay_Us()`: они обнуляют и останавливают счётчик. Дедлайн
  `paj_readGesture()` строится либо на собственном запуске SysTick
  (`PAJ_OWN_SYSTICK=1`), либо на бюджете итераций (`=0`).
* **Отладка стоит флэша:** `PAJ7620U2_DEBUG` подтягивает `printf`
  (~+200 Б в проекте с уже подключённым выводом в UART).
* **Аппаратные тайминги датчика** (частота обновления 120 Hz, диапазон
  жестов 5…15 см, угол 60°, скорость 60…600 °/с) заданы datasheet и не
  настраиваются драйвером.
* **Жесты ладонью и пальцем ведут себя по-разному.** Широкая ладонь даёт
  скачок размера/яркости объекта и ложный `Forward/Backward`; поэтому по
  умолчанию (`PAJ_Z_OVERRIDES_XY=0`) начатый боковой жест Z-флагом не
  отменяется. Если нужен намеренный push/pull пальцем — соберите с
  `-DPAJ_Z_OVERRIDES_XY=1`. При остаточных ложных Z-срабатываниях поднимайте
  `PAJ_ZDIR_THRESHOLD` (банк 0 `0x48`) до `0x48…0x55`.

## Если МК перезагружается

Повторная печать баннера `PAJ7620U2 gesture driver init...` означает сброс МК.
Это **не** переинициализация датчика: её путь печатает
`SENSOR HANG (i2c=…), re-init...` и `Sensor recovered.`. Пример печатает причину
последнего сброса по флагам `RCC->RSTSCKR` и очищает их, поэтому каждый
следующий запуск однозначен:

```
PAJ7620U2 gesture driver init...
Reset: POR PIN
Mode: INTERRUPT (INT=PC3)
PAJ7620U2 ready. Gesture mask 0x0F, wave off
```

| Строка | Причина | Что делать |
|---|---|---|
| `PIN POR` / `POR` | включение питания или просадка VDD | питание: см. ниже (типовая причина) |
| `POR SW` | просадка VDD, после которой отладчик/WCH-Link переподключился (SW-сброс) | питание; при повторе отключить WCH-Link и проверить с внешним питанием |
| `PIN` | внешний сброс по NRST | кнопка, WCH-Link, auto-reset USB-UART (DTR/RTS при открытии порта) |
| `SW` | программный сброс | перепрошивка через WCH-Link |
| `IWDG`/`WWDG` | сторожевой таймер | в этом примере не включается |
| `(RCC reset flags not cleared)` | RMVF не снял флаги | флаги недостоверны, смотрите пункт про питание напрямую осциллографом |

**Циклические перезагрузки** (баннер повторяется каждые ~0.3 с, строка `ready`
обрывается на полуслове) — это почти всегда просадка питания: датчик с момента
`paj_init()` непрерывно сканирует и его ИК-светодиод даёт импульсы 720…860 мА,
средний ток десятки мА при пиках до ампера. Диагностика по шагам:

1. Прошейте диагностическую сборку: `pio run -e power_test -t upload`
   (или добавьте `-DPAJ_EXAMPLE_POWER_TEST=1` в `build_flags`). В ней датчик
   переводится в suspend (≈15 мкА), печатается только `alive N` каждые 500 мс.
   * перезагрузки прекратились → виноват ток датчика / его питание;
   * перезагрузки продолжаются → смотрите МК, NRST, WCH-Link (датчик ни при чём).
2. Эквивалент без пересборки: отключите у модуля VDD/VLED — нормальная прошивка
   напечатает `ERROR: PAJ7620U2 not responding!` и останется жива.
3. Проверьте напряжение: **VDD ≤ 3.6 В**, **VLED ≤ 4.2 В**. Модуль без
   встроенного стабилизатора нельзя питать от 5 В — это даёт как раз такой
   «циклический ребут».
4. Питание: отдельная цепь/LDO для VLED, bulk ≥100 мкФ + 10 мкФ + 100 нФ у
   выводов модуля, короткий обратный провод, земля светодиода соединена с землёй
   логики. Вывод 3.3 В WCH-Link (≈100 мА) для этого модуля не подходит.

**Подтверждено на стенде:** при питании модуля от WCH-Link 3.3 В МК уходит в
POR-цикл через ~20 с непрерывных жестов (пачки сбросов каждые 30…40 мс), а та же
плата с `power_test` (датчик в suspend) держит `alive` больше 250 (две минуты) без
единого сброса. То есть МК/NRST/WCH-Link исправны, не хватает тока шины 3.3 В на
ИК-светодиод — лечится только отдельным питанием VDD/VLED.

Исключено измерениями: драйвер не содержит путей сброса; `HardFault_Handler`
в примере — бесконечный цикл (был бы «завис», а не рестарт); сторожевой таймер
не включается; стек драйвера измерен `-fstack-usage` — максимальный кадр 48 Б
(`paj_exti_init`), функции драйвера ≤20 Б, `main` 36 Б при 256 Б в линкере.
Отчёт о причине сброса стоит ~216 Б флэша и отключается
`-DPAJ_EXAMPLE_RESET_INFO=0`.

## Сборка и проверка

```bash
pio run                 # сборка примера
pio run -t upload       # прошивка через WCH-Link
pio run -t size         # размер прошивки
```

Эталонная сборка `examples/basic` (LTO включён): **RAM 528 Б, Flash 11108 Б**
при 2048 Б RAM / 16384 Б флэша. CI (`.github/workflows/ci.yml`) собирает
20 конфигураций с `-Wextra -Werror` и проверяет потолки размера.
